## Implemented class repair

`templates/hcls-librechat/sequence-analysis.py` provides deterministic saved-result
analysis. The existing Evo2 skill points to the typed `evo2-continuation` phase;
shared workflow/schema/image wiring is owned separately by the release owner.

CLI: `sequence-analysis.py --plan PLAN --output-dir OUT`.

Plan fields: `reference_file`, optional `reference_id`/`title`, and nonempty
`cases` containing `id`, `start_zero_based`, `input_file`, `result_file`, and
`operation_file`. Typed live workflows require operation files; the standalone
helper can explicitly retain unavailable identity if one is omitted. FASTA
record selection is explicit; plain DNA is also accepted. Relative files resolve
against the plan directory. Per-case `sequence_mode` defaults to `suffix`, the
current hosted contract; `prefix-and-suffix` must be explicitly declared and
the prefix verified. No heuristic sequence-field search or coincidental-prefix
stripping occurs.

Four outputs: `metrics.json`, `rows.csv`, `report.md`,
`completion-manifest.json`. The completion manifest is published only after
closed-file readback and binds plan/helper/source hashes and all three artifacts.
Conflicting old files are preserved; identical completed outputs are reusable.

The helper measures counts, sequence alphabet, GC with explicit all-position
versus ACGT denominators, reference agreement, comparable seed/repeat pairs,
actual operation identities, and timing units. Original requests, seeds and
returned sequences are retained. Underfill, overfill, ambiguous output and
unsuccessful operation status remain visible. Probabilities/logits, when
genuinely present, retain their sampling meaning; missing values remain unknown.
No likelihood, variant-effect score, affinity, biology or billing is invented.
