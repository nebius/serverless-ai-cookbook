## Source changes

- `describe_scientific_workflow` returns selected phase schemas directly from
  the existing validator, guaranteed versus conditional output filenames and a
  short file-backed example. No new executor, model loop or admission route.
- The existing `plan_file` v2 dispatch was already implemented; its misleading
  legacy-only description is repaired and tested for identity reuse, frozen
  source plans/inputs, complete reports and no model transport for CPU work.
- Execution guidance consistently uses the installed qualified tool names.
  Longer scripts/plans use bounded logical file writes, not giant one-shot
  arguments. Original wait, output, iteration and phase deadlines are unchanged.
- The typed `mindeval` phase accepts full retained record paths, reuses the
  existing score renderer and publishes exact full records/transcripts, CSVs,
  measured counts and hash-bound report. Reuse-only analysis no longer carries
  an unconditional instruction to query the provider catalog. Missing scores
  remain unavailable; no clinical winner or statistical superiority is inferred.
- Explicit `sole-protein-chain` selection records the actual observed chain
  and rejects zero/multiple chains. Structure chain pairs can derive only from
  the already hash-bound residue correspondence, with conflicting explicit maps
  rejected; the existing evaluator still validates both hashes and all positions.
- The batch skill now describes the installed file uploader/whole-study path,
  canonical result filenames and RFdiffusion's human-readable unconditional
  provenance note, not a fictional constraint syntax. Model parameters still
  come from the live contract and user settings; defaults must be labelled.
