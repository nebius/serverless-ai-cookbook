# Bounded natural acceptance of unattended studies

**Prepared, not executed.** These ten prompts are customer-shaped successor
studies for the new durable client, not evidence that it works or a second
twelve-hour throughput campaign. The deployment remains **one LibreChat
instance per user**. Users may intentionally share a tenant bucket; this does
not authorize shared execution instances or multiple concurrent supervisors for
one user.

The machine-readable [manifest](manifest.json) binds every prompt SHA-256,
fresh/reused workload, required mounted input path, bounds and independent
acceptance checks. Only the corresponding `prompts/scientist-NN.txt` goes to
the agent. The manifest and previous corrected reports are evaluator material,
not instructions to coach the agent through a passing tool sequence.

## Scope

| Scientist | New bounded work | Explicit reuse / limitation |
| --- | --- | --- |
| 01 | One OpenFold2 ubiquitin prediction and experimental-reference report | Public1UBQ reference; no old prediction counted as fresh |
| 02 | Boltz2/Protenix ×1ACB/2PTC: four predictions and complex analysis | Existing frozen inputs only; poor reference agreement remains useful evidence |
| 03 | One four-sample Proteina batch and one ≤20-candidate BoltzGen batch | Public PD-L1 bundle; report search replicas/yield/roles honestly |
| 04 | One RFdiffusion→ProteinMPNN→ESMFold2-Fast dependency chain | Historical Mosaic/BindCraft context explicitly reused, not requalified |
| 05 | Four DiffDock requests/16poses, one GenMol request/16unique molecules | Existing public chemistry inputs; no MolMIM rerun |
| 06 | Six public chloroplast windows × two seeds,12continuations | No unsupported likelihood or variant-effect claim |
| 07 | Two PhenoAge batches/32rows and two AltumAge order variants | Existing public feature mapping; numerical reproducibility, not clinical validation |
| 08 | Two full-source drafts plus one expected short-source no-report attempt | All four ASR transcripts reused; WER/source checks are newly recalculated |
| 09 | Complete six-record MindEval transcript/criterion report | **Reuse only**, zero new consultations/judgments |
| 10 | One recorded-video transfer plus one two-episode LeRobot augmentation, four numeric export formats | Real recorded source; physical action-label validity remains a separate limitation |

There are at most33 new top-level model operations and three clinical draft
attempts in these prompts. A logical batch may contain multiple GPU stages;
LeRobot may make native child calls. Draft provider calls, internal stages,
polls and uploads must be recorded separately, not hidden in or added to the
top-level model count. This is an intent ceiling, not a success denominator.

The new durable schema has **no MindEval/workshop admission stage**. Scientist09
therefore tests its historical counting/report failure using retained complete
records. This is not fresh workshop inference, fresh judge calibration or
workshop restart qualification. Do not silently route a workshop request
through an ordinary native-App contract. This bounded scope was chosen by the
campaign owner rather than starting another workshop implementation.

## Release-owner execution recipe

1. Bind the actual deployed source/image and provider configuration per user;
   verify supported publication paths and the stop-first supervisor handover.
   Freeze the existing mounted source objects' sizes and hashes. Check every
   required directory contains the stated dataset, not merely an empty folder.
   Where this manifest gives a historical hash, require exact matching bytes.
2. Confirm a fresh output directory for each prompt. A rerun is a new labelled
   cohort with a recorded output-path-only prompt change, not an overwrite or
   permission to recreate an already accepted request.
3. Submit exactly the frozen prompt through the actual browser, then observe
   the agent-created whole-study plan and accepted identity. Do not replace it
   with an operator-authored plan or supply helper commands after a failure.
4. Close and reopen the browser after durable acceptance; inspect Runs and
   progress without a follow-up chat turn. No accepted durable study means the
   unattended gate has not passed, even if model work happens elsewhere.
   Any test-owned instance restart is separately coordinated by the owner.
5. Let independent users share ordinary constrained capacity. Keep waiting
   visible, preserve the actual policy and distinguish capacity deferral from
   lost work, duplicate admissions, client stalling or false completion.
6. Download every final declared artifact via real UI links. Reopen formats,
   compare bytes, independently recalculate metrics and verify that the final
   report agrees with the typed measured outputs. Preserve original failures
   and classify any ordinary continuation or technical/method coaching.

Final checks must use the actual sources/results, not historical numerical
predictions as success targets. The expected counts for frozen ALOHA, retained
ASR and reused MindEval records are input/measurement invariants, not constants
to hardcode into general production helpers. New clinical accepted-fact counts
may vary: test their agreement with the actual typed output, not a fixed32.

Unsupported preparation, missing analysis coverage or an incomplete natural
plan must stay visible. This preparation does not assert that every requested
analysis is already expressible in the new durable schema. It also does not
award a scientific, medical, physical or platform-wide readiness verdict.

Origins and historical defects are preserved in the
[ten-persona checkpoint](../evidence/20260919-twelve-hour-checkpoint/personas.md),
[clinical v42 evidence](../evidence/20260919-natural-clinical-v42/README.md), and

The live deployer retains private conversations, credentials and signed
artifacts outside Git; these fixtures contain none of them.
