# Scientific workbench usability review and implementation plan

Inspected the live deployment on 2026-09-09 before the redesign. Browser evidence
is in `output/playwright/before-{landing,model-selector,evo-chat-error,mobile}.png`.

## Observed failures

- The model picker mixes six saved tutorial agents with chat providers. Every
  tutorial agent fixes the conversational model to GLM-5.3-Flash.
- The `Nebius Scientific Models` custom chat endpoint fetches the entire native
  scientific catalog. Selecting Evo2 and sending “Reply with hello.” reproduces
  a chat error: `400 status code (no body)`. These tools have model-specific
  inputs and cannot be exposed as ordinary chat-completion models.
- Token Factory is configured with one default model and `fetch: false`, even
  though authenticated discovery returns 23 models, including many chat LLMs.
- OpenAI and Anthropic endpoints are disabled by `ENDPOINTS=agents,custom`.
- Tutorial clicks switch the selected agent/model. GROMACS has a visible card
  but no matching model spec, so clicking it does nothing. Audio advertises a
  future service in the primary workflow grid.
- The landing page repeats product branding and technical model lists, with
  little distinction between learning, running an example and comparing models.
- Repeated `/api/convos/new/subagents` 404 requests add noise on the landing page.
- Gateway acceptance found independent runtime problems: MSA Search returned an
  upstream 500 after three platform attempts; several schema-valid serving calls
  returned generic MCP errors. UI changes cannot repair those platform runtimes.

## Intended experience

1. Choose a conversational LLM from a provider-grouped model picker. Show readable
   model names, preserve the selected LLM when choosing a workflow, and keep
   gateway models exclusively available as scientific tools.
2. Offer a useful selection of Token Factory chat models. Enable native OpenAI
   and Anthropic providers with per-user key setup when no deployment key exists.
   Label setup requirements; do not imply an unconfigured provider has passed
   an inference test. Keep the working GLM model as the initial default.
3. Give every chat-model preset the same scientific instructions, deployment
   skills, gateway and search capabilities. A model change must retain those
   capabilities and the conversation history.
4. Replace the old grid with six goal-oriented starts: explore available models,
   fold a protein, dock a molecule, explore sequences, investigate biological
   age/imaging, and research the literature. Cards prepare a useful prompt and
   an explanation of needed inputs; they never submit compute on click.
5. Keep input requirements and unavailable file capabilities explicit in the
   workflow. Surface operation IDs and runtime failures without invented output,
   silent model substitution or repeated submission.
6. Make the page readable on mobile and desktop, in light and dark themes, with
   keyboard-accessible controls and clear selection feedback.

## Verification before delivery

- Parse the generated config against the pinned LibreChat schema; test shared
  and per-user key modes, chat-model allowlists and consistent tool/skill setup.
- Build the actual image and exercise a fresh isolated local instance.
- Switch between at least two Token Factory LLMs; send a real chat and a gateway
  discovery request. Check that the request uses the selected LLM and tools.
- Open OpenAI and Claude choices without keys and test the setup dialog; run real
  inference only when a corresponding provider credential is available.
- Click every tutorial, verify prompt preparation and unchanged LLM selection,
  then test a complete small structure workflow and failure reporting.
- Inspect desktop/mobile screenshots and console/network errors. Keep the
  existing live endpoint until the replacement is verified; avoid deleting its
  conversation storage during rollout.

## Acceptance observations during implementation

- Browser: all six cards prepare unique editable prompts, preserve Qwen 3 30B,
  and issue zero chat/compute requests. Three provider groups only; native models
  and legacy tutorial agents are absent from the chat picker. Mobile390px has no
  horizontal overflow; both native provider-key dialogs open.
- Found and fixed another pinned-client bug: `expiresAt: null` (no key) was
  interpreted as `never` (a saved, non-expiring key). OpenAI/Claude now show a
  setup notice and block sending when no key exists. No actual OpenAI/Claude
  inference was tested because no provider credentials were available.
- The initial full tool catalog used198,485 tool-definition tokens and prevented
  Qwen's38,912-token context from accepting even a small first message. Deferred
  model-tool loading, including the first-request `mcp_all` expansion path,
  allows Qwen to discover schemas and complete scientific work.
- Qwen retrieved the exact OpenFold2 schema, then submitted one synthetic16-residue
  example via the compatible `invoke_model` route. Operation
  `d77ed2a3-3626-4c9b-8e1d-9722a2e68dc9` succeeded; status and result were retrieved
  without resubmission. It did not follow the preference for the named typed tool.
  Its final prose miscounted the sequence and overstated confidence: reporting
  instructions were tightened, but this is not proof that LLM summaries are
  scientifically reliable. Preserve and inspect the underlying result.
- GLM completed a real Tavily literature lookup with the original AlphaFold2
  paper link. The old wrapper had no network deadline and requested an additional
  generated answer; the replacement uses basic source search, a20-second deadline,
  bounded result count and explicit non-secret errors.
- A separate21-model,512-output-token synthetic function-call probe returned17
  actual function calls. Gemma3 returned prose; MiniCPM-V4.5 returned400; GPT-OSS120B
  and Kimi-K2.7-Code exceeded45seconds. The shipped picker therefore includes17
  tested Token Factory choices plus4 OpenAI and3 Claude choices, not embeddings,
  dedicated endpoints, or the four unqualified models. A small probe establishes
  tool-format compatibility, not complete workflow correctness for every LLM.
- Slow title generation previously left chats named New Chat and triggered404
  polling. Qwen now generates titles; a10-second first-prompt fallback handles
  unavailable title models while retaining upstream title/abort policy.
- Successful independent gateway acceptance before the UI redesign also includes
  DiffDock and resumed ESMFold2 batch output/hash verification. MSA Search failed
  upstream500; ProteinMPNN, GenMol, MolMIM, OpenFold3 and Qwen3-8B returned generic
  MCP errors. These are platform-runtime blockers, not repaired by this UI change.

Reproducible checks live in `tests.py`, `scripts/browser-smoke.js` and the opt-in
`scripts/probe-chat-models.mjs`. Browser screenshots are local evidence, not shipped
assets. Do not claim universal model readiness or multi-tenant acceptance.
